# 引用 M7，为什么还要看那颗棋子？

棋谱助手回答：“第七手黑棋在第八行第五列，见 M7。”点击引用，M7 真的存在。这条回答能算对吗？

先在纸上画两行棋盘，像程序一样从 0 数格子。黑棋依次放在 `(7,0)、(7,1)、(7,2)、(7,3)`，白棋穿插在下一行。第七手正是第四颗黑棋。把行号和列号分别加一，给玩家看的位置就是**第八行第四列**。错的那一格，恰恰藏在一条真的引用后面。

这个小实验有两张桌子。第一张桌子找资料，第二张桌子写答案。先把 M7 直接交给第二张桌子；再让第一张桌子按手数找卡后转交。同一问题，两路都能答出第四列。接着只从第一张桌子的目录抽掉 M7，得到“证据不足”。把卡放回，直接交给第二张桌子，故意把第四列抄成第五列。这一次资料找对了，答案依然错。

你也可以拿两张便签复现：一张写 `M7 = 黑 (7,3)`，一张写答案。先盖住第一张，再揭开它并把答案列号改大一。分别问三件事：答题时看到了该看的资料吗？引用指到它吗？答案说的事实和它一致吗？三个问题有三个答案。一个总分没法告诉你该修找资料的步骤，还是修写答案的步骤。

这是固定棋谱和可控制答题器的演示，没有调用在线模型；它检验的是评分方法能不能抓到这类错，不是某个模型在真实对局中有多准。

## 用公开棋谱复现

在仓库根目录用 Java 21 和 Maven 运行下面的命令。

```sh
mvn -B -f backend/pom.xml verify
```

打开 [RuleEvidenceTest.java](../backend/playroom-review-contract/src/test/java/dev/playroom/review/RuleEvidenceTest.java)，找到 `seventhMoveKeepsItsOwnCellAndUsesPlayerFacingCoordinates`。它从九手终局里按编号找出 M7，分别检查证据中的格子 `(7, 3)` 和给玩家看的文字「第7手黑棋落在第8行第4列」。要复现实验里的反例，可以在自己的副本里仅把测试期望的「第4列」改为「第5列」后重跑。M7 仍然能找到，失败报告会直接标出列号差异。
